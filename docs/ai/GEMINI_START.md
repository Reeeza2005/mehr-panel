# Gemini Start Protocol — Mehr

این فایل پروتکل شروع کار Gemini در پروژه «مهر» است.

## 1. قبل از هر کاری

قبل از تغییر هر فایل یا ارائه راه‌حل فنی، ابتدا این منابع را بررسی کن:

1. `docs/ai/AI_RULES.md`
2. `docs/ai/PROJECT.md`
3. `docs/ai/TODO.md`
4. `docs/ai/DECISIONS.md`
5. `docs/ai/CHANGELOG.md`
6. `MEHR_MANUAL.md`
7. فایل‌ها و کد واقعی پروژه در صورت نیاز

اگر اطلاعات موجود در حافظه چت با فایل‌های پروژه یا کد واقعی مغایرت داشت، فایل‌ها و کد واقعی منبع حقیقت هستند.

## 2. قانون عدم حدس

هرگز درباره ساختار پروژه، فایل‌ها، توابع، رفتار برنامه یا وضعیت پیاده‌سازی حدس نزن.

اگر اطلاعات کافی نداری:
- ابتدا فایل یا کد مربوطه را بررسی کن.
- رابطه بین فایل‌ها و اجزای مرتبط را بررسی کن.
- سپس نتیجه‌گیری کن.

## 3. قانون توسعه مرحله‌ای

کار را به مراحل کوچک و قابل بررسی تقسیم کن.

در هر مرحله:
1. وضعیت فعلی را بررسی کن.
2. مشکل یا هدف مرحله را مشخص کن.
3. تغییر لازم را انجام بده.
4. تست مناسب را اجرا کن.
5. نتیجه واقعی تست را گزارش کن.
6. اگر تغییر مهمی انجام شد، مستندات مربوطه را همان زمان به‌روزرسانی کن.

همزمان چند مرحله عملیاتی را بدون نیاز انجام نده.

## 4. قانون یک مرحله در هر پیام

کار عملیاتی را مرحله‌به‌مرحله انجام بده.

در حالت عادی فقط مرحله بعدی را ارائه کن و منتظر نتیجه آن بمان.

کاربر برنامه‌نویس حرفه‌ای نیست؛ دستورات باید دقیق، قابل اجرا و همراه با محل اجرای آنها باشند.

## 5. قانون مستندسازی رویدادمحور

مستندسازی به تعداد چت‌ها یا پیام‌ها وابسته نیست.

پس از هر تغییر مهم، مستندات مرتبط را بررسی و در صورت نیاز همان زمان به‌روزرسانی کن.

این موارد شامل:
- تغییر معماری
- تغییر مهم کد
- اضافه یا حذف قابلیت
- رفع Bug مهم
- تغییر رفتار برنامه
- تصمیم فنی مهم
- تغییر ساختار پروژه
- تکمیل یک مرحله مهم
- تغییر وضعیت واقعی پروژه

است.

هرگز منتظر تعداد مشخصی چت یا پیام نمان.

## 6. ثبت تصمیم‌ها

تصمیم‌های مهم معماری و فنی باید در:

`docs/ai/DECISIONS.md`

ثبت شوند.

تصمیم قدیمی را بدون دلیل حذف نکن. اگر تصمیم تغییر کرد، وضعیت تصمیم قبلی را مشخص کن و تصمیم جدید را ثبت کن.

## 7. ثبت تغییرات

تغییرات واقعی پروژه باید در:

`docs/ai/CHANGELOG.md`

ثبت شوند.

مواردی که فقط پیشنهاد یا ایده هستند، تا زمانی که واقعاً اجرا نشده‌اند، به عنوان تغییر انجام‌شده ثبت نشوند.

## 8. وضعیت کارها

وضعیت کارها در:

`docs/ai/TODO.md`

نگهداری می‌شود.

هیچ کاری را فقط به دلیل اینکه طراحی یا پیشنهاد شده، Done اعلام نکن.

Done فقط زمانی ثبت شود که اجرای واقعی و تست مناسب انجام شده باشد.

## 9. معماری اصلی Mehr

معماری فعلی پروژه:

Mehr = رابط کاربری اصلاح‌شده Nahan + هسته BPB

Mehr خودش VPN یا Core مستقل نیست.

ساختار کلی:

User
  ↓
Mehr Panel
  ↓
Modified Nahan UI
  ↓
BPB Core / Worker
  ↓
Cloudflare

BPB UI هسته اصلی رابط کاربری Mehr نیست.

قابلیت‌های مفید Nahan باید تا حد امکان حفظ شوند.

قابلیت Smart Router نیز بخشی از برنامه Mehr است.

## 10. قانون تست

هرگز تستی را که انجام نداده‌ای انجام‌شده اعلام نکن.

بین این موارد تفاوت بگذار:

- کد تغییر کرده
- تست شده
- تست موفق بوده
- تست ناموفق بوده
- هنوز تست نشده

## 11. قانون امنیت

API Key، Token، Password، Secret و اطلاعات حساس را در فایل‌های عمومی، مستندات عمومی یا Commit قرار نده.

## 12. قانون تغییرات کوچک

قبل از تغییر گسترده، ابتدا کوچک‌ترین تغییر لازم را مشخص و اجرا کن.

قابلیت‌های فعلی نباید بدون دلیل حذف یا خراب شوند.

## 13. قانون تشخیص خطا

قبل از رفع Bug:
1. خطا را مشاهده و بررسی کن.
2. علت احتمالی را با بررسی کد مشخص کن.
3. فایل‌های مرتبط را بررسی کن.
4. سپس اصلاح را انجام بده.
5. بعد از اصلاح، تست مناسب انجام بده.

صرفاً بر اساس متن خطا حدس نزن.

## 14. قانون پایان هر مرحله مهم

پس از تکمیل یک مرحله مهم:
- وضعیت واقعی را بررسی کن.
- TODO را در صورت نیاز به‌روزرسانی کن.
- تصمیم‌های جدید را در DECISIONS ثبت کن.
- تغییرات واقعی را در CHANGELOG ثبت کن.
- در صورت تغییر اطلاعات معماری یا قواعد، فایل‌های مربوطه را نیز به‌روزرسانی کن.

## 15. دستور شروع

بعد از خواندن این فایل، ابتدا منابع اصلی پروژه را بررسی کن.

سپس قبل از هر تغییر، به صورت کوتاه اعلام کن:

- وضعیت فعلی پروژه چیست.
- درخواست فعلی مربوط به کدام بخش است.
- برای بررسی اولیه چه فایل‌هایی را باید ببینی.
- فقط مرحله بعدی چیست.

سپس منتظر نتیجه مرحله بعد بمان.

## اصل نهایی

هدف این پروتکل این است که Gemini در طول پروژه «مهر» بر اساس حافظه موقت چت تصمیم نگیرد، بلکه بر اساس مستندات نسخه‌بندی‌شده و کد واقعی پروژه کار کند.

اصل اول:

**دقت و صحت مهم‌تر از سرعت است.**

اصل دوم:

**اگر مطمئن نیستی، بررسی کن؛ حدس نزن.**
